# 留白 · 我的时间计划

适合手机的中文时间规划 PWA。设置日常作息和每周固定安排，自动显示每天的空闲时段，并在空档中安排任务。

## 功能

- 按周查看每天的空闲时长，按日查看完整时间线。
- 设置起床 / 睡觉时间；工作、通勤等固定安排按星期重复。
- 创建待安排任务、寻找最早空档、手动选择日期和时间。
- 防止任务时间重叠，支持编辑、删除、完成和移回待安排清单。
- 待办卡片和任务编辑窗口的“立即开始”会启动倒计时，并在当天日程显示进行中的任务。
- 页面底部持续显示剩余时间与预计结束时间，支持暂停 / 继续。“结束并完成”会保存实际开始到结束的时段，任务划线保留在已完成清单。倒计时到时也自动记录并完成。
- 任务卡片可展开每次执行的起止时间、实际跨度和专注时长；暂停包含在跨度中但不计入专注时长，跨午夜分别显示在两天的日程中。
- 已有执行记录的任务以实际记录展示日程，不再重复占用原计划时段；记录会随 JSON 备份导出与导入。
- 倒计时按绝对截止时间保存，刷新、后台恢复、跨午夜均能恢复正确剩余时间。
- 到时显示弹窗并尝试播放提示音，可手动开启系统通知（依浏览器支持）。
- 自动保存到当前浏览器，可导出 / 导入 JSON 备份。
- 可添加到手机主屏幕，首次成功加载并缓存后支持离线使用。
- 纯静态网页，无依赖，无服务器，无 API 密钥。

首次打开没有预填私人安排。默认的 07:00–23:00 只出现在设置表单中；保存作息后才计算空闲时间。当前作息以一个自然日为单位；凌晨入睡可将当天边界设为 00:00，跨午夜固定安排拆成两条。

## 最简单的 GitHub Pages 上线方式

1. 登录 GitHub，新建一个仓库，例如 `time-planner`。免费账号建议选择 Public（公开仓库仅包含网页代码，你在网页里输入的计划不会提交到仓库）。
2. 解压项目，把以下文件和 `icons` 文件夹上传到仓库根目录：
   `index.html`、`style.css`、`app.js`、`core.js`、`timer.js`、`focus.js`、`records.js`、`manifest.webmanifest`、`sw.js`、`icons/`。
3. 打开仓库 **Settings → Pages**。
4. 在 **Build and deployment** 下选择 **Deploy from a branch**，Branch 选 **main**，目录选 **/(root)**，点击 Save。
5. 等待 Pages 部署完成，打开页面中显示的正式地址，通常为 `https://你的用户名.github.io/time-planner/`。

所有资源使用相对路径，支持仓库子路径部署；无需修改域名配置。

### 使用附带的自动部署工作流

若通过 Git 上传完整项目（包括 `.github/workflows/pages.yml`），在 **Settings → Pages** 中将 Source 设置为 **GitHub Actions**，然后在 Actions 页面运行 **Deploy to GitHub Pages**。之后每次推送到 `main` 都会先运行核心测试，再自动发布网页。工作流只打包网站资源，不发布测试或文档。

## 添加到手机桌面

- **iPhone / iPad**：用 Safari 打开部署后的 HTTPS 地址 → 分享 → 添加到主屏幕 → 添加。
- **安卓**：用 Chrome 打开地址 → 菜单 → 安装应用 / 添加到主屏幕。浏览器支持时，页面中的“添加到手机桌面”也会触发安装。
- 最后一步需要在手机上点击，网页无法静默添加桌面图标。
- 本地直接双击 HTML 文件无法完整运行模块与离线功能，请部署到 HTTPS 或使用下方本地服务器。

## 数据与备份

数据保存在当前浏览器的 localStorage；不会上传到 GitHub，不会自动跨设备同步。清理浏览器、切换浏览器或更换域名可能导致看不到原计划，请先在“作息设置”中导出备份。部分 iPhone 版本的桌面应用与 Safari 存储可能不同，可通过备份导入迁移。完成任务后仍保留该时间段的占用，以便回顾实际安排。

计时与提醒：网页在前台运行时会到时弹窗，并在浏览器允许音频时播放提示音。手机锁屏、关闭网页或切换到后台时，系统可能暂停网页，无法保证准时响铃或通知；重新打开会按实际截止时间恢复或显示到时提醒。iPhone 的系统通知支持取决于系统版本和主屏幕安装状态。计时期间会尝试保持屏幕常亮，但取决于设备支持与省电设置。进行中的计时仅保存在本机；结束后的执行记录包含在任务清单的导出备份中。修改任务时长不改变正在运行的计时，需重新点击“立即开始”才会重启。

离线功能需首次联网成功缓存网站。网站更新时使用联网资源；必要时关闭所有页面后重新打开以启用新的离线缓存版本。

```sh
python3 -m http.server 4173
# 打开 http://localhost:4173
npm test
```

测试覆盖空档合并与裁切、星期重复与指定日期、冲突检测、备份校验和日期边界。已用 Chromium 验证手机 / 桌面布局、作息设置、任务安排与完成、刷新保存和离线重新打开。手机系统实际安装需在真实设备上完成。
